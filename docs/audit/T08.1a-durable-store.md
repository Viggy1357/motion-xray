# T08.1a — durable asset/job metadata

20 October 2026, Malaysia time. FR02, FR03, FR12. Internal prerequisite for T03/T08.1;
the browser upload-to-analysis flow is not delivered by this component.

## Delivered

- SQLite schema version 1, WAL, foreign keys, short atomic mutations, explicit closure
  and rollback; future database versions fail closed.
- Private asset metadata and owner-scoped jobs/idempotency. UUID lease tokens fence
  stale workers even when the same worker name reclaims an expired lease.
- Atomic claim, heartbeat, stage checkpoint, terminal success/failure, cancellation and
  deletion tombstones. Publication checks live lease, job and asset under one write lock.
- Raw expiry prevents processing while report/job status uses its own TTL. Deletion
  immediately denies metadata access and publication. No physical file deletion yet.
- Path, clock/deadline overflow, hash and machine-readable failure-code validation.
  Contracts remain 0.2.0; dependencies, exercise thresholds and scoring remain unchanged.

Implementation: `services/api/app/store.py`; tests: `tests/unit/test_job_store.py`.
Authenticated owners and actual media validation are caller responsibilities in T03.
Opaque result keys do not establish a valid report or approved pose artifact; consumers
must validate the artifact and ownership. No routes are activated by this work.
