## Draft boundary (unaccepted)

The proposed `supervise_once` claims one job from the existing
SQLite Store, checkpoints POSE and renews its unique lease while a child process
runs. Trusted synchronous callbacks construct an argument vector and validate the
child's output contents. The latter returns one basename for a small result manifest.
The draft parent checks that file is regular, nonempty, at most1MiB and within its own
attempt directory before publishing its relative key through fenced Store.finish.
Large frame artifacts are outside this manifest size limit; their validation belongs
to the future child adapter. A zero child exit alone never establishes analysis success.

Each attempt uses `attempts/<job UUID>/<lease token>/`, created exclusively. A collision
preserves existing content. Only an owned unsuccessful attempt is removed; parent
directories and other attempts remain. Root/ancestor symlinks and lexical traversal
are rejected, controlled directories use0700 and the published manifest uses0600.

Cancellation, deletion, expiry and reclaim revoke publication through existing Store
fences. The parent stops the process group with TERM then KILL as needed and waits
for its direct child on every exit, including unexpected exceptions and interrupts.
It also kills surviving group descendants after a successful leader exit. Orphaned
grandchild zombies belong to container init; production containers need an init/reaper.
The future child must keep subprocesses in the inherited group. This is process
supervision within a trusted private artifact root, not an OS security sandbox.

Timeouts, launch errors, nonzero exits, invalid output and attempt collisions use
constant error codes. Unexpected database or programming errors propagate after
cleanup; lease loss is expected and does not overwrite the newer job state. Trusted
callbacks must be quick: the subprocess deadline cannot preempt synchronous callbacks
or bound SQLite lock latency. A crashed parent can leave an old attempt directory;
physical retention/recovery remains a separate task.
