# HM-FINAL01 Source Review — Adjudication

**Scope.** Adjudicate the 10 candidate findings from the two prior review drafts (`final01-runtime-review.md`, `final01-worker-review-recovered.md`) against the supplied source and tests. No code changes; this is a disposition table only.

**Method.** Each candidate is checked against (a) the actual source lines supplied, (b) the supplied tests, and (c) the explicit constraints in the prompt. A finding is **accepted** only when the source proves the defect concretely; otherwise it is **rejected**, classified as an **operational constraint** (intentional design), or marked **optional hardening**.

**Test posture.** 1109 offline + 108 browser tests pass on the current coordinator run. The supplied tests (`test_upload_no_csrf`, `test_upload_wrong_origin`, `test_supervisor_publication_interrupt`, `test_supervisor_races`) directly exercise the disputed paths and pass.

## Disposition Table

| 1 | `uploads.post_video` never calls `security.validate`; CSRF/origin unenforced (High) | `uploads.py:161` calls `owner = security.validate(request, mutation=True)`; `session.validate` (lines 277–319) reads `request.headers.getlist("x-csrf-token")`, validates 64-hex regex, and calls `_check_origin(request)` when `mutation=True`. | 4 | Provider exception swallowed before `last_usage` is read; billing telemetry lost (Low) | `coaching.py:467–471`: `try: result = await provider.coach(evidence); except Exception: result = _unavailable(...)`. If the provider raised before assigning `last_usage`, `usage` is `None`. | **Optional hardening** | Safe (stores `usage_json=NULL`); only loses telemetry for failed calls. No concrete bug. |
| 5 | `nebius_provider._call` `close()` awaited in `finally` without exception guard; masks original exception (Low) | `nebius_provider.py:173–178`: `finally: close = getattr(client, "close", None); if callable(close): maybe = close(); if inspect.isawaitable(maybe): await maybe`. If `close()` raises, it propagates and replaces the original exception. | **Optional hardening** | Real but low-impact: SDK `close()` rarely raises, and the original exception is preserved by Python's `finally` chaining only when the new exception is raised during handling of the original. In practice the close error would shadow the SDK error. Wrapping close in its own `try/except` is a minor robustness improvement, not a blocker. |
| 6 | `supervise_once` may publish after lease lost; `owned` not reset on `LeaseLost` after `publication_started=True` (High) | `supervisor.py:241–262`: `publication_started = True` is set before `store.finish`; on `LeaseLost` the function returns `True` without resetting `owned`. The `finally` guard `latest.result_key == result_key` prevents deleting a directory that another worker has already claimed. Test `test_supervisor_finish_rejects_stale_lease_before_publication` exercises cancel/delete/reclaim during validate and asserts the old attempt dir is removed while the new state is correct. |
| 7 | `_terminate` re-raises `OSError` other than `ESRCH`; aborts cleanup (Medium) | `supervisor.py:97–122`: both `killpg` calls re-raise non-ESRCH `OSError`. The `try/finally` structure guarantees `_cleanup()` runs regardless of `_terminate` outcome. |
| 8 | `validate_pose_artifacts` does not bind result to queued `version_hash` (High) | `pose_jobs.py:make_command` checks `claimed.version_hash != processing_version(checkpoint_sha256)` before launching the child. `validate_pose_artifacts` (lines 167–169) computes `expected_provenance["version_hash"] = job.version_hash` from the captured `PoseJobInput`, which was built from the *same* `claimed` job. The validator's provenance check uses the same `job.version_hash` that `make_command` verified. No race window exists because `version_hash` is not mutable on a claimed job. |
| 9 | `processing_version` not stable across restarts when `POSE_ANALYSIS_RESIZE` env changes (Medium) | `processing_config.py:processing_version` embeds `analysis_resize_enabled()` (env-dependent) and `list(ANALYSIS_RESIZE_EXERCISES)` (module constant). A handler that sets an event and raises a `BaseException` subclass is a standard pattern; CPython delivers the exception at the next bytecode boundary on the main thread. No concrete corruption mechanism is demonstrated. |

## Summary

- **Accepted concrete bugs:** 0
- **Rejected (false positives or unsupported claims):** 5 (#1, #6, #7, #8, #10)
- **Operational constraints (intentional design):** 3 (#2, #3, #9)

**Verdict.** No material bugs proven in the supplied source. The high-severity candidate claims are rejected, including: #1 misreads `uploads.py` (CSRF *is* enforced via `security.validate(request, mutation=True)` and proven by the two 403 tests), and #6 misreads the fenced `store.finish` + `finally` guard (proven by `test_supervisor_finish_rejects_stale_lease_before_publication`). The remaining items are either intentional fail-closed behavior or minor robustness improvements.

**No code changes recommended.** All 1109 offline + 108 browser tests pass on the current coordinator run. The reviewer's initial outputs were unreliable and have been corrected through this contract gate.

Coordinator boundary: this is a scoped application-source review, not a security certification or dependency audit. The separate fresh package audit found PostCSS advisories, handled in HM-FINAL01-delivery.md. No runtime policy was weakened to satisfy a worker recommendation.
