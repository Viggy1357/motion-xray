# T08.1b.2 real pose child and validated publication

## Delivered boundary

`services/api/app/pose_jobs.py::run_pose_once` calls the accepted supervisor, which
alone claims the job. Its command callback retrieves the owner-scoped input from the
real Store, writes an exclusive private typed request and launches
`services/pose/child.py` in the attempt's process group. The bridge is worker-side
code; it enables no HTTP route and imports no MediaPipe SDK. The existing pure sample
selector and bounded frame reader are reused rather than reimplemented.

The child verifies its input, builds the accepted proxy/timestamp map, then calls
MediaPipe on the **original registered video**, covering its full eligible duration.
It reads the actual content-addressed JSONL artifact and rejects a sequence with no
usable observations. It emits a typed manifest with an explicitly pose-only report:
empty rep/metric/reference records, null score and unavailable coaching. Empty rep
records mean segmentation was not run, not a measurement of zero repetitions.

`PoseJobInput` and `PoseJobArtifacts` live in contracts with generated JSON schemas.
They are additive private artifact models under contracts0.2.0/format`pose-job-v1`;
OpenAPI, public endpoints and frontend types are unchanged. No new dependency,
exercise threshold, scoring policy or provider choice was introduced.

Before publication the parent verifies request bytes/hash, job/video/exercise/version
binding, checkpoint revision, the embedded/file timestamp-map agreement, proxy bytes
hash and limits, and the **pose file's content hash**, distinct from the model hash.
It validates each selected source index/timestamp and the complete expected30Hz
sample set. Source/proxy frame counts need not equal pose sample counts. Missing
joints remain gaps. Lexical symlinks/traversal are rejected; files use0600, controlled
directories0700. Only Store.finish with the live unique lease can publish the manifest.

The child has no fake-provider runtime flag, database writes or LLM calls. CLI failures
return only `POSE_CHILD_FAILED`; raw request contents and internal paths are not echoed.
The supervisor retains ownership of cleanup and process reaping. FFmpeg processes
inherit the child's group. A trusted private root and quick validation callbacks are
assumptions; this is not an OS sandbox or a physical retention service.
