## Prioritized findings

### A01 — Contract model imports fail (blocker)

`packages/contracts/contracts/base.py` sets `ser_json_inf_nan='strict'`, which is not
accepted by pinned Pydantic 2.9.2. Model class construction raises SchemaError. The
FiniteFloat validators are useful, but compiling a file never exercised this defect.
Fix configuration and validate non-finite/null behavior in T02.1.

### A02 — Existing commands/CI cannot establish a runnable baseline (blocker)

`tests/contracts/__init__.py` collides with the installed top-level package in the
default pytest layout. Ruff/mypy fail as above. Setup/dev/test/analyze/evaluate/cleanup/
seed scripts advertise work but exit successfully without doing it. The API image
does not contain the test tree/dev tools and ordinary package installs are non-editable;
mounted sources alone do not guarantee installed code reflects edits. CI omits image
builds, frontend production build, integration and actual user-flow checks.
Create a documented reproducible test/runtime strategy in T02.1.

### A03 — Core product behavior is absent (blocker)

Pose, geometry, segmentation, metrics, alignment, scoring, reference loading and jobs
are explicit stubs. `apps/web/app/page.tsx` is a heading. `services/pose/worker.py` is
startup logging plus commented pseudocode. No working user journey has been demonstrated.
Complete the real lat-pulldown slice before more scaffold or exercise expansion.

### A04 — Reference provenance and score guards are not implemented (blocker for scores)

`ReferenceProfile` lacks `authoritative`/source provenance, and extra fields are forbidden.
No reviewed trajectory/ranges exist, no builder exists, and no scoring guard enforces
D007. The old `.agents/tasks/plan.md` proposes keyed placeholder tolerance values;
do not implement that step. Only measured trajectories and reviewed rules are admissible.
Owning a clip does not establish a valid technique benchmark. T06/T07.

### A05 — Contracts cannot carry or enforce the full intended result (high)

`Metric` permits null with no reason. Rep temporal order/scorable consistency and score/
coverage bounds are unchecked. `CoachingResult.observations` is a list of strings,
not observations with validated rep/metric/source IDs. `AnalysisResult` exposes a scalar
score without a defined per-rep breakdown or top-level null-score reason structure.
Define typed payloads, cross-field rules and coordinated schema versions before consumers.
Use response models in real routes so generated OpenAPI actually includes them.

### A06 — Evidence path is not ready for live exposure (high)

`refresh_evidence` enables Tavily through env alone and has only an operator-auth TODO.
Compose publishes port 8000 on all interfaces. No request bounds/rate/budget guard exist.
The API image installs base providers, not the search extra; a live selection cannot be
assumed callable. Tavily methods are async signatures around blocking client calls and
store a timeout they never apply. Generic exceptions become retryable timeouts and
raw exception text is returned to callers. Fix before enabling a live hosted route.

### A07 — Evidence review/filtering claims exceed behavior (high)

CachedSearchProvider reads any URL-bearing JSON without checking approved status,
exercise/variant or full record validity. Source-tier substring matching can be spoofed.
Discovery's max_results/allowlist parameters are not enforced in orchestration; text
snippets are dropped from draft records and no persistence/review loop exists. No API
tests cover unauthorized live access, cache filtering or fallback. Source ranking does
not certify technique. T01b/T10.

### A08 — Reproducibility and dependency maintenance are incomplete (high before release)

There are direct pins but no committed resolved lockfiles, unpinned hatchling/build
dependencies, mutable Docker base tags and non-frozen pnpm installs. The OpenAI/httpx
incompatibility already manifested in Kiro's log. Next.js 14.2.15 is flagged vulnerable
by its package warning and [upstream advisory](https://nextjs.org/blog/security-update-2025-12-11).
Patch against current supported releases in T02.1 rather than treating every old pin as safe.

### A09 — Configuration/data acceptance gaps (high for measurement validity)

The first exercise's YAML is omitted from the fixed three-exercise test list. Smoothing,
gap handling, minimum excursion, cycle bounds and visibility masks are not fully versioned
in configs. `shoulder_drive` lacks a tested implementation and is described as a muscle
engagement proxy in a YAML comment; joint motion cannot justify an activation claim.
The sole clip exceeds the 30-second default. No ground-truth labels or held-out corpus
exist. Preserve actual timestamps and declare a chosen short test interval. T01/T04/T05/T13.

### A10 — Ownership/retention/deletion are design intent (high before real user hosting)

No session-owned assets/jobs, private artifact access, cancellation/lease protection,
CSRF/rate controls or executable TTL cleanup exist. OPERATIONS describes policy as if
implemented; the delete route is 501 and cleanup deletes nothing. The original brief
uses 24h media/pose versus seven-day reports; newer operations copy says seven-day
derived artifacts. Resolve pose retention explicitly before persistence implementation.
T03/T08/T14 must demonstrate these behaviors, not only document them.

### A11 — Browser routing is not connected (medium, before UI integration)

Compose supplies a browser `/api` base, API routes are `/v1`, and Next has no proxy/rewrite.
No generated client types exist. Choose a same-origin contract and verify it in the
browser slice; separately successful web/API builds cannot prove connectivity. T02.1/T11.

### A12 — Task and requirement drift obscures progress (delivery blocker)

TASKS still says curl first although D005 says lat pulldown first; T01b mixes evidence
and reference work before pose is available. The original detailed targets became vague
in EVALUATION. Several FR numbers changed meanings without a crosswalk, especially
FR06 metrics -> catalogue and FR12 runtime inference -> status/honesty. Later policies
and scratch task state disagree on implementation progress. Preserve decisions and
map requirements explicitly; use TASKS plus DELIVERY as maintained handoff records.
