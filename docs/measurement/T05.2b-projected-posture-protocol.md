# T05.2b projected posture measurement protocol

**Status:** research_pending_calibration
**Authoritative:** false
**Version:** 0.1
**Date:** 22 October 2026
**Scope:** 2-D projected torso angle for lat-pulldown posture observation. Not calibrated anatomical lean, not world 3-D, not a clinical score.

## 1. Input

- `PoseFrame`: dictionary of named 2-D joint detections with per-joint confidence/reason flags.
- Required joints for a side: visible-side shoulder and hip on the **same anatomical side**.
- Image dimensions `width`, `height` as positive integers.
- A frozen `ProjectionAxis(version, axis_id, up_xy, positive_cross_sign)`.

## 2. Axis convention

- `up_xy` is a 2-D non-zero vector in pixel coordinates. For image-up it is `(0, -1)`.
- `positive_cross_sign` is exactly `+1` or `-1`.
- With image-up and sign `+1`, positive means image-right; reversing the sign reverses
  that convention. This is not an anatomical backward-lean or gravity claim.

## 3. Per-frame computation

1. Retrieve shoulder and hip for the requested side.
2. Apply the existing invalid-joint priority: `missing_joint` → `invalid_joint` → `interpolated_joint` → `missing_coordinates` → `degenerate_geometry`.
3. Restore pixel aspect ratio: `p = (normalized_x * width, normalized_y * height)`.
   Compute torso vector `t = shoulder_px - hip_px` in that pixel plane.
4. Compute unit vectors `u = up_xy / |up_xy|` and `v = t / |t|`.
5. Angle:
   ```
   angle = atan2(cross(u, v) * positive_cross_sign, dot(u, v)) * 180 / pi
   ```
   Result in `[-180, 180)` degrees.
6. Return `AngleObservation(metric='torso_axis_angle', space='projected_2d', value, reason)`.

## 4. Window summary

Inputs:

- Sequence of `AngleObservation` samples with strictly increasing finite PTS.
- Closed interval `[start_s, end_s]`, `0 <= start < end`.
- `max_gap_s > 0`.
- `circular: bool`.

Rules:

- Select samples inside `[start, end]`; no padding or interpolation.
- Reject if `< 2` selected samples → `insufficient_samples`.
- Reject if any selected sample is invalid → `missing_observation`.
- Reject if `first_pts - start > max_gap_s` or `end - last_pts > max_gap_s` → `partial_window`.
- Reject if any consecutive observed gap `> max_gap_s` → `timestamp_gap`.
- Invalid summary: all numeric measurement fields are `null`; PTS and counts are retained.

For valid summaries:

- Linear stats: `min`, `max`, `excursion = max - min`, `start_value`, `end_value`, `end_change = end - start`.
- Circular stats: unwrap each consecutive difference along the shortest arc in `[-180, 180)`. If any difference is exactly `180°`, set reason `ambiguous_rotation` and do not fabricate direction. Min/max/end values may lie outside `[-180, 180)`; the first value is stored raw.

## 5. Diagnostic configs

Two frozen configs are used:

- `lat-posture-observation-v1.json`
- `lat-posture-roi-observation-v1.json`

Both specify source paths, windows, side, axis and the explicit processing gap limit
`max_gap_s=0.1`. Output directory is a CLI argument. Neither config supplies technique
tolerances, scoring weights or model-training parameters.

## 6. Validation checks performed

- Synthetic fixture tests: perpendicular torso, tilted axis, mirroring sign, aspect ratio, `+179°` to `-179°` wrap, null/gaps/boundaries, mixed side/order, boolean rejection, degenerate geometry, global priority, translation/rescale invariance, repeated identical frames.
- Regression fixture includes analytic 30° torso and 2° wrap cases.
- Offline runner verifies input pose-artifact bytes against the stored SHA-256 digest.

## 7. Checks that remain insufficient for real-video accuracy

- No qualified human angle labels.
- No calibrated gravity or seat-back baseline.
- Camera-up is image-up, not anatomical backward lean.
- No bar/chest localization; wrist proxy does not satisfy the bar-endpoint requirement.
- No per-rep phase labels (`pull_start`, `turnaround`, `return_end`).
- No approved reference profile or validated tolerances.
- 3 Codex rough pixel labels are unquantified; residuals are not an accuracy estimate.
- Side/diagonal view eligibility is asserted by config, not validated per frame.

## 9. Relation to rubric

This protocol implements raw observables only. It does not implement:

- `torso_start_lean` (M1) baseline calibration.
- `torso_dynamic_excursion` (M2) per-rep extraction.
- `elbow_interior_rom` (M3) per-rep events.
- `upper_arm_torso_angle` (M4) per-rep events.
- `chest_bar_endpoint` (M5) bar/chest localization.
- `return_extension` (M6) endpoint events.
- `tempo_control` (M7) segmentation.
- `head_shoulder_setup` (M8) head metric.

See `docs/measurement/LAT-PULLDOWN-RUBRIC-v0.1.md` for the full research rubric and calibration handoff.
